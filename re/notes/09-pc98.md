# 09 — The PC-98 version (1.02J): disk, EXE, FM driver, sounds

The PC-98 release (VETTE! 1.02J, "Sound by … H.Nagata(J)") shares the DOS codebase. It adds a YM2203
(OPN) FM driver with **four songs** and nothing else. Its in-game sounds are the DOS PC-speaker
programs moved to the PC-98 beeper, so **no in-game sound has an FM version**. Two songs replace DOS
speaker tunes (title, winner), and two play where DOS is silent (pre-race menus, lost race).

Code: `src/assets/pc98_disk.*` (files), `src/sound/pc98_sound.*` (hosted driver), `src/sound/pc98_cues.*`
(the PC-98's music cues on the DOS game), `src/sound/pc98_backend.*` (GameAudio backend),
`src/tools/vette_pc98.cpp` (listing, extraction, WAVs).

Addresses: PC-98 addresses are image-relative `SEG:OFF` like the DOS ones (notes 01), and Ghidra shows
them +1000h on the segment (`1FFD:1292` for `0FFD:1292`). DOS addresses are `3009:…` / `124A:…` as in
`re/symbols.csv`.

## 1. Input: the player's copy

`Pc98Files::open(Game/PC98/)` takes the plain files when `VETTE.EXE` is there. Otherwise it tries each disk
image in the folder by extension (`hdi nhd thd fdi d88 88d d98 98d nfd hdm tfd xdf dup img ima raw hdd`)
until one holds `VETTE.EXE`. The format is recognized from the contents:

| Format | Recognized by | Layout |
|---|---|---|
| HDI / FDI (Anex86) | dword header: 0, type, header size, data size, sector size, sectors, heads, cylinders | sectors follow the header |
| NHD (T98-Next) | `T98HDDIMAGE.R0` | header size, cylinders, heads, sectors, sector size at 110h |
| THD (T98) | extension | 256-byte header (cylinders), 8 heads × 33 × 256 bytes |
| D88 | image size at 1Ch = file size | track table at 20h, 16-byte sector headers (C H R N …, length) |
| NFD r0 | `T98FDDIMAGE.R0` | 163 × 26 sector ids of 16 bytes at 120h, data after the header in table order (C = FFh: unused) |
| raw | anything else | plain sectors |

D88 and NFD sectors are placed by their own C/H/R ids, using the most common sector size; odd sectors
are dropped. NFD r1 is refused with a message. Only the shipped HDI was available as a real image. The
other formats are covered by synthetic images in `tests/assets_pc98_disk.cpp`.

FAT volumes are found in three ways: a boot sector at offset 0 (a floppy), boot sectors in the first 4 MB
at 256-byte steps, and the PC-98 partition table. The table needs geometry, which comes from the image
header or from the first boot sector found (sectors per track, heads, hidden sectors). A PC-98 2HD
floppy without a BPB (1024-byte sectors, 8 × 2 × 77) is assumed when its first FAT starts with FEh.
FAT12 and FAT16 are supported. The `VETTE.EXE` closest to the root wins, and its directory is the game.

**Robustness.** Every read is bounds-checked against the image. A cluster chain fails on free, bad,
out-of-range or **revisited** clusters. Each directory cluster is walked once (cycles, `.`
self-references), with a depth limit of 16 and at most 65,536 listed entries. A damaged game file is
skipped and reported; a damaged `VETTE.EXE` rejects the image. Limits: 16 MB per file, 64 MB per game,
and 4 GB per image.

### The shipped image (`VETTE.hdi`, 5,330,944 bytes)

- HDI header: type 5, header 4096, data 5,326,848 bytes, 512-byte sectors, 17 sectors, 4 heads, 153
  cylinders. `VETTE.raw.img` is the same data without the header.
- Sector 0: IPL (`EB 0A 90 90 'IPL1'`). Sector 1: PC-98 partition table with one entry: mid A1h (bootable
  DOS), sid 81h, IPL and start at C1 H0 S0 (LBA 68 = 8800h), end C145, name `MS-DOS 6.20`. Entries are
  32 bytes: mid, sid, 2 unused, IPL sector/head/cylinder, start sector/head/cylinder word, end
  sector/head/cylinder word, 16-byte name.
- Volume at 8800h: OEM `NEC  6.2`, 1024-byte sectors, 2 per cluster, 1 reserved, 2 FATs of 4 sectors,
  512 root entries, 4930 sectors, BPB media F8h but **FAT id FEh** (so the reader only requires
  F0h–FFh followed by FFh), 17 sectors/track, 4 heads, 68 hidden. That gives 2452 clusters: FAT12.
- Root: `IO.SYS`, `MSDOS.SYS`, `COMMAND.COM`, `AUTOEXEC.BAT`, directory `VETTE`. `\VETTE` holds the 32
  game files: `VETTE.EXE` (202,350 bytes), 28 `.PIC` files (`TITLE VX RIDER GARAGE DASH GEARS LEFTWHEE
  RPM1 SPEED TACHS WHEELBAR SPIN HORIZON0-2 CRASH0-1 LOSER0-3 WINNER HIGHSC PENALTY TICKET EGAPIC
  EGASKILL MAPPIC`), and `ANIM.DAT`, `CONFIG.DAT`, `SCORE.DAT`. They match `Vette_PC-98_JA/extracted/`
  byte for byte (test `pc98_disk_player_files`).

## 2. The EXE

The MZ header is 600h bytes (96 paragraphs) with 248 relocations and **no packing**. Entry is
`0000:0005`, SS:SP `4729:0400`. Segments:

| Segment | Contents | DOS counterpart |
|---|---|---|
| 0000 | All game code, about FFD0h bytes. The DOS far libraries (3FFC keyboard, 4021 highway, 4160 vehicle, 422F serial) are merged in and called near. | 3009 + far segments |
| 0FFD | The FM driver, 1CA5h bytes, self-contained | (none) |
| 11C7 | A disk routine using the PC-98 disk BIOS (INT 1Bh). It is called once from 0000:008D when DS:2ADF = FFh and sets DS:2ADF to 0/1. Probably copy protection; not analysed. | (none) |
| 123E | Game data (DS), mostly DOS offset − 1Ah | 124A |
| 2EE5 | File names (`title.pic`…) and more | 0ACB (the DS used by DOS for the same code) |
| 2D5B, 3106, 3788, … | Picture and other buffers (by relocation counts; not analysed) | |

The only far calls go to the driver (10 relocations: init, shutdown, and 8 calls of the entry point) and
to 11C7.

## 3. The FM driver (segment 0FFD)

It is hand-written assembly. It sets DS = ES = CS and uses nothing else but ports 188h/18Ah (OPN address
and status / data), the interrupt controller (00h/02h master, 08h/0Ah slave) and one interrupt vector.

### Layout (offsets in the segment)

| Offset | Contents |
|---|---|
| 0000 | IRQ table: 4 × {w vector address, b IMR port, b mask bit, b slave EOI (0 = none), b master EOI}. Indexed by SSG port A (reg 0Eh) bits 7-6, the board's jumper: 0 INT0 (IRQ3, vector 0Bh), 1 INT6 (IRQ13, 15h), 2 INT41 (IRQ10, 12h), 3 INT5 (IRQ12, 14h) |
| 0018 | FM F-numbers for note nibbles 0-C (5 unused, 0): C=26Ah … B=48Fh. A4 = 410h at block 4 is 440.1 Hz at 3.9936 MHz |
| 0032 | SSG tone periods, same nibbles: C=EE8h (16.35 Hz, C0) … shifted right by the octave |
| 004C | Volume 0-15 → TL attenuation: 37 35 31 2D 2B 28 25 23 20 1D 1A 18 15 11 10 0D |
| 005C | Algorithm 0-7 → carrier operator mask: 08 08 08 08 0C 0E 0E 0F |
| 0067 | Idle track: DFh 00h (rest 95 ticks, end). Stopped tracks loop on it |
| 006A | 6 music tracks × 2Eh bytes |
| 017E | 6 effect tracks × 2Eh bytes |
| 0292 | Variables: 292 saved vector, 296 vector address, 298/29A song's voice/envelope tables, 29C marker count, 29E fade step, 2A2 return value, 2A4-2A7 IRQ table entry, 2A8 master attenuation, 2A9 its refresh count, 2AA/2AB mixer (reg 07h) shadows, 2AC noise owners, 2AD noise period, 2AE reg 27h shadow, **2AF music tracks playing**, 2B0 effect tracks playing, 2B1 board present, 2B2/2B3 effect/music busy (the ISR skips them) |
| 02B4 | Song list (below) |
| 11B1 | Code |

### Entry points

| Address | Call | Job |
|---|---|---|
| 0FFD:11B1 | far, from 0000:001A | Init. Status FFh means no board: returns AX = FFFFh, [2B1] = 0. Otherwise it reads the IRQ jumper, mutes (1B64: key-off on FM 0-2, SSG volumes 0), sets mixer 07h = B8h (tones on, noise off, port B out), hooks the vector to 1671, unmasks the IRQ, writes 27h = 30h (reset flags), and sets [2B1] = 1 |
| 0FFD:1261 | far, from 0000:050D (exit) | Shutdown: mute, timers off, mask the IRQ, restore the vector |
| 0FFD:1292 | far | Function AH with argument AL (DX); returns AX = [2A2] |
| 0FFD:1671 | interrupt | Status bit 1 (timer B): music tick 16CA unless [2B3]. Bit 0 (timer A): effects tick 16E4 unless [2B2]. Each is acknowledged by writing 27h = shadow \| 20h/10h, then EOI |

Functions (AH):

| AH | AL | Job | Used by the game |
|---|---|---|---|
| 0 | 0 | Fade-out step = DX (see bugs) | no |
| 0 | 1 / 2 | Marker count: read and decrement / read and clear (counts `EE` commands) | no |
| 0 | 3 / 4 | Joystick 1 / 2 (SSG port B select 8Fh/CFh, then read port A) | no |
| 1 | song (0 = stop) | Play music: tracks 006A, timer B | **yes** (1-4, 0) |
| 2 | song (0 = stop all) | Play as effect: tracks 017E, timer A, takes channels from the music | no |
| 3 | | Stop music | no (uses AH=1 AL=0) |
| 4 | song / 0 | Stop effect(s) | no |
| 5 | song / 0 | Is the effect playing / which are | no |
| 6 | attenuation | Master music attenuation [2A8], refreshed over the next 6 ticks | no |

### Timing

Music runs on **timer B**. The default is C8h = (256 − 200) × 1152 / 3.9936 MHz = **16.15 ms** per tick.
Songs set their own value with `F4`. Effects run on timer A (24h/25h, default 080h = 16.15 ms). Each
tick runs, per track: 1867 (duration, gate, next event), 1777 (SSG envelope), 1743 (LFO), and for
music also 1701 (fade).

### Song list (02B4)

Each song has a length word (the next song is at + length), then words relative to the song's start:
the FM voice table, the SSG envelope table, and the track table. The track table holds 6 × {w track,
w loop (0 = none)}, and the tracks map onto FM 1, 2, 3 and SSG A, B, C. Play walks the list by length
**without checking the song number**: 5 and above read code. The list ends exactly at the code (11B1).

### Track state (2Eh bytes)

+0 channel: FM 0-2, or SSG 90h/A2h/C4h (bit 7 = SSG, bits 4-6 = its noise bit, low nibble × 2 = tone
register). +1 FM carrier mask, or SSG volume register. +2 flags: 01 channel taken by an effect, 04 reload
the voice when it is given back, 08 effect track, 10 SSG envelope running, 20 LFO on, 40 tie, 80 key on.
+3 duration left. +4 gate left. +5 volume 0-15. +6 SSG octave. +7 gate ratio /8. +8 song number.
+A position. +C loop. +E detune. +10 base frequency. +12 voice / envelope. +14 voice table. +16 fade
attenuation. +18…+22 LFO: delay, period, step, state. +24 envelope position. +26 envelope mark
(Ax). +28 envelope level. +29/+2A envelope loop count / start. +2C/+2D hold count / held byte.

### Sequence bytes

| Byte | Meaning |
|---|---|
| 00 | End of track: continue at the loop, or stop (decrements [2AF]) |
| 01-7F `n` | Note for `n` ticks, then a note byte: bits 4-6 octave (FM block), bits 0-3 note (0-4, 6-C) |
| 80-DF | Rest for (byte & 7Fh) ticks |
| FF `id` | Voice (FM: table entry with that id; SSG: envelope) |
| FE `v` | Volume 0-15 |
| FD `w` | Detune (added to the frequency) |
| FC | No operation (also E0-ED) |
| FB `n` `note` | Note with an 8-bit duration |
| FA `n` | Rest with an 8-bit duration |
| F9 | Tie: no key-off before the next note |
| F8 `m` | SSG mixer bits for this channel |
| F7 `p` | SSG noise period (shared, register 06h) |
| F6 `c c w` | Repeat end: count, initial count, back offset (word, relative). F6 with a big-endian word whose bit 15 is set is a repeat start: it resets the matching end's count |
| F5 `d p w` / `00 x` | LFO (vibrato): delay, period, frequency step; `00 x` turns it on (x ≠ 0) or off |
| F4 `t` | Tempo: timer B (music) or timer A (effect, C0h+ scaled) |
| F3 / F2 | Volume +1 / −1 |
| F1 `q` | Gate: notes sound for duration × q / 8 ticks |
| F0 `w` | Break: on the last pass of a repeat, jump past its end |
| EF `r v` | Write OPN register r = v |
| EE | Marker count + 1 (for function 0/1-2) |

**FM voice** (26 bytes, table entries stride 1Ah): an id, then 24 register bytes in register order for
30h, 34h, 38h, 3Ch (DT/MUL), 40h… (TL), 50h… (KS/AR), 60h… (AM/DR), 70h… (SR), 80h… (SL/RR), then the
FB/ALG byte for B0h. Volume adds table 004C (plus the fade and master attenuation) to the carriers' TL.
Key on is 28h = channel | F0h.

**SSG envelope**: {id, length, 0, bytes…}, stepped once per tick while the note sounds. A byte
00-7F is a level, and the output volume is level × (volume + 1) / 16 minus the fade. Control bytes:

- 8x: jump back to the mark set by Ax (a sustain loop), or end in silence if there is no mark.
- 9x: repeat the current level.
- Ax: set the mark here.
- Bx / Cx: level +x / −x (clamped 0-15).
- Dx: loop end. Ex: loop start, with count x.
- Fx: hold the last byte x more ticks (with B/C this makes ramps).

Key-off silences an SSG note at once: there is no release.

### Bugs and quirks (none reached by the game)

- **Fade (function 0/0)**: once a track's fade attenuation turns negative it is stopped, and
  `dec [2AF]` runs again **on every later tick**. The "music playing" count then wraps below zero. The
  host fades by itself (`Pc98Sound::fade_out`).
- The song number isn't checked (see the song list). The effect player, marker count and joystick
  functions are never called.

## 4. Hosting it (`Pc98Sound`)

The driver segment is copied out of the player's `VETTE.EXE` and checked first. Byte signatures must
match at init, entry, ISR, the track-end instruction and the busy wait, and the song list must walk
to exactly 4 songs. If the module isn't at 0FFD, it is found by its ISR. It is loaded at 1000:0000 on
a scratch 286 (`host::Cpu`), with an `IoBus`:

- 188h: status (`FmChip::status`), and the address latch on writes.
- 18Ah: data writes to the chip. Reads return the last written value, and FFh for 0Eh, the jumpers:
  INT5, joystick released.
- Interrupt controller writes are ignored.

Init runs once; play, stop and the ISR are far calls / interrupts that return to a host-callback stub
(budget 4 M cycles, or the driver is declared stuck and the chip is muted). The chip renders at its own
rate (ymfm's YM2203 at clock/4 = 998.4 kHz). Every 256 chip samples (0.26 ms) a raised IRQ runs the ISR
— the same rate and timer behaviour as on a PC-9801-26K, so tempo, gates and envelopes are the
original's. Output: box-filtered to the output rate (the SSG's square waves would alias otherwise),
10 Hz AC coupling, gain 0.5 (loudest song peaks 0.54; the DOS speaker emulation is ±0.25). The FM/SSG
balance is ymfm's raw sum; the board's analogue mix wasn't measured.

`loops()` counts passes of a looping song: a watch on 0FFD:1890 (a track read its end byte) counts the
wraps of each looping track. `playing()` reads [2AF].

**Validation** (`tests/sound_pc98_driver.cpp`, `vette_pc98 wav`):
- Lengths from an independent decoder of the song data (Python, from the format above) match the
  hosted driver to the 10 ms render block: title first pass 106.56 s vs 106.6, menu 31.53 s vs 31.55
  (the tests require ±30 ms), winner 6.20 s and loser 4.65 s (plus a 1.5 s tail in the WAVs: 7.7 / 6.2).
- Tuning: the strongest spectral peak of each 0.34 s window sits a median 2-8 cents from A440 equal
  temperament (FM vibrato and detune account for the rest). The tables themselves imply 3.9936 MHz.
- A hand-assembled stand-in driver (same signatures) checks the extraction, port routing, timer-B rate
  (62 ticks = 1.0015 s ± 3 ms) and a driver that never returns.
- Deterministic: two instances render identical samples.

## 6. In-game sounds: the beeper port

The DOS speaker driver was rewritten for the PC-98 beeper: 8255 port C bit 3 via 37h (06h on, 07h off),
and the frequency on 8253 counter 1 (3FDBh). Sequences, requests and the engine slide are the DOS ones.

| Sfx (sound_events.h) | DOS | PC-98 | Difference on the PC-98 |
|---|---|---|---|
| engine | seq 92A6 (divisor 92A8), 93EA, 9428, pitch table 932A | seq F734 (F736), F886, F8C4, table F7AC | same divisors, faster timer clock: pitch × 1.67 (8 MHz-class, 1.9968 MHz) or × 2.06 (2.4576 MHz) |
| garage_rev | cs:92A8 = DF00h/1300h (8A65, 8BCB, 8C02) | F881 (cs:F736), e.g. from 0000:9100 | as engine |
| skid | seq 927E via 948A | seq F70C via F936 | raw divisors 100/300/200/100 → 20/6.7/10/20 kHz, vs 501/464/481/501 Hz on DOS |
| siren | seq 9292 via 9483 | seq F720 via F931 | same notes (E5/C5) from a note table |
| title_tune | seq 9304 via 9470 | seq F786 via F907, **never called** | FM song 1 instead |
| win_tune | seq 92C4 via 9578 | seq F746 via FA2A, **never called** | FM song 2 instead |
| crash, crash_car, crash_rail, hit_pedestrian | noise 9498 | F940 | clicks port **61h** (it reads 35h, then writes 61h): not the PC-98 beeper, so presumably silent on hardware (unverified) |
| gear_grind | noise 94C9 | F96E | in/out 61h: presumably silent likewise |

The noise callers pair up: 3009:16D2/1720/1CF6/0999/1F4F ↔ 0000:13ED/1439/1A03/08D2/1C04. One of
3009:7EC5/7F79 ↔ 0000:7693 (not resolved).

PC-98 beeper details:
- **Clock tables**, picked by 0:0501 bit 7: F6F0 for 1.9968 MHz, F6DE for 2.4576 MHz. Each holds the
  ch0 divisor, the beep divisor and 7 notes C5 D5 E5 F5 G5 A5 B5 (F6F0: EE8h … 7E6h, in tune). The
  2.4576 MHz table's ch0 divisor 1F65h gives **305.8 Hz, not 291.3**, so on those machines the race
  clock (`race_seconds = ticks / 291`) and the sounds run 5% fast.
- **Note encoding**: a sequence divisor below 10h is a note index; larger values are raw divisors. The
  code's `shr cl,4` octave shift is dead, because the `cmp bx,10h; jae` test excludes 10h. So the tunes'
  "C6" entries (value 10h) play divisor 16, which is about 125 kHz: silent (in F746 and F786, which are
  unused anyway).
- Gone from the PC-98: DOS's unreferenced one-shot beeps 92AE/92B4 (95A4/95C0). The PC-98 adds a small
  API: request bits set/clear/get F99E/F9A4/F9AC; toggles F7C0 (sound) and F7C6 (engine); get/set/on/off
  F7CC/F7D1/F7D6/F7DD.
- Timer ISR 0000:FA89 (DOS int08 98FD + timer_work 9918): ticks, then every 4th tick F8C4 + F7F7, with
  no BIOS chain.

## 7. DOS ↔ PC-98 correspondences

Matched automatically for every symbol in `re/symbols.csv` (at the time of writing), with fixes by hand:

- **Code**: the DOS instruction stream from the symbol is tokenized (mnemonic plus operand shape, without
  values) and looked up as a 10-instruction window in the PC-98 code segment. A unique window is
  extended while the tokens agree ("n ins." = the length of the agreement; "from +k" = the window starts
  k instructions in). Failing that, a global alignment of 3009 with 0000 is used ("aligned": approximate
  for code that changed).
- **Data**: operand pairs in all matched code vote. "n/m refs" = n of m matched references agree.
  "interpolated" = no direct reference, but the neighbours within 20h on both sides shift alike.
- DS data mostly shifts by −1Ah (DOS 124A:2C71 cam → 123E:2C57), with local differences
  (124A:2C69 → 123E:2C52).

Spot checks of random matches all agreed instruction for instruction (with shifted addresses). Treat
"aligned" and "interpolated" entries as leads.
